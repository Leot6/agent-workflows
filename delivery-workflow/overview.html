1. 服务目的

问题：让多个 LLM 编码会话在无人看守下，把一个已规划好的变更集落成一串经过独立评审、满足项目提交规范、可追溯到计划的 git 提交；同时让唯一稀缺的资源——owner 的注意力——只在真正需要判断时被打断，并且打断时手里有可裁决的证据。

对象：一个 owner（做 Class U 决定、push、裁定分歧）；可选的 pilot 会话（转发裁定、重启、观察）；由 ferry 驾驶的 author / reviewer 会话；author 派出的 implementer 子代理。

立场（design/architecture.md §1）：判断流向最便宜的仪器；记录即完成；缺席 ≠ 故障；能力声明而非名字；一切可度量的都印出实例而不是数字。

2. 核心框架

2.1 四个根设计

① 一张表、一个推导

每个阶段在 config/stages.tsv 里声明 scope / session / owed / verdicts / next / manifest；lib/owed.sh 是唯一读表的推导。emit 的拒绝、ferry 的推进检查、prompt 的清单都来自同一列表——不存在第二份。

② 一个原子存储

lib/state.sh：每个 surface 一个文件，头部 #v=1 gen= sum=md5 writer= t=，tmp+rename、flock、写者类别（ferry/session/operator/gate/watchdog）。rc 0/1/2/3 把「无」与「坏」分开：fault ≠ absent。

③ 能力而非名字

后端是声明文件 config/backends/<name>.kv（launch 命令、能力、屏幕签名正则、modal 应答、settle 时间），只有一个结构适配器 backends/pty_tmux.sh。换 CLI = 加一个 .kv 并跑一次 onboarding probe。

④ 判断流向最便宜的仪器

emit 时机械门（caps、claims 表、env sweep、结构、行号钉、commit 规范）→ author 自循环 refine → 独立 reviewer → owner。越贵的仪器越少被打扰。

2.2 单元与阶段

topic → slice → stage。蓝框 = 合约冷会话（独立性是买来的）；其余按需复用暖会话。

plan-validate→ split⇄split-check→ spec→precheck⇄revise→impl→postcheck⇄fix→turnover × N slices → close-out
  • 拓扑级：plan-validate 读 plan；split 产出 charters.md 与机器索引 id:risk:repo:title[:after=NN]；split-check 复推导八条粒度准则；close-out 出治理报告并提 history consolidation。
  • 切片级：spec（含 claims 表、flip gate、commit-unit 表）→ precheck（spec-ready 契约逐条）→ impl（author 派 implementer，逐 commit-unit 登记 record.sh progress）→ postcheck（独立底线，acceptance 亲自重跑，每条发现打 leak_class）→ turnover（指针 + 增量，供下一 slice）。
  • 完成只有一种方式：session/record.sh emit——校验 nonce（单次、角色绑定）、封闭词汇的 verdict、角色字段、owed 集合，跑 emit 时机械门，再追加 handoff 记录。Stop hook 让会话在没有记录前无法结束回合。

2.4 活性、收敛与经济

活性栈（lib/watch.sh）：进程 pid+starttime → Stop-gate 阻断计数 → 心跳 → CPU 速率下限 → 屏幕分类（working / awaiting_input / error_retryable / quota_exhausted / backend_overloaded / modal.* / unknown）→ 协议空闲事件（idle_prompt）→ nudge 梯子 → 时钟跳变豁免。时间只经 _wt_now/_wt_sleep 两个接缝读取，自检在虚拟时钟上确定性地跑。

收敛：attempt 指纹（prompt 体 ⊕ owed 哈希 ⊕ manifest 输入 ⊕ 上次失败类别，K=4）→ no_novelty；review 双循环用 severity-trend 谓词；split 循环用索引字节不变的 fixpoint。

经济：每 (slice, stage, round) 的尝试预算；slice / topic 墙钟预算只计工作时间（停车时间记入 credit）；relaunch 是一次 redrive。

停车词汇（封闭）：dead · idle · stall_record · stall_mismatch · owed_miss · no_novelty · budget_attempts · budget_wallclock · template_error · plan_changed · workflow_changed · unknown_modal · unknown_screen · operator_interference · operator_stop · store_fault · backend_quota · backend_overloaded · class_u · blocked · disagreement · push_gate · broken。每个都有 operations.md §3 的 playbook。

2.5 配置、钉与学习闭环

  • 配置四层：defaults.kv ⊂ 用户 config.kv ⊂ <ws>/config/topic.kv ⊂ slice.NN.<agent>.kv；schema.kv 封闭词汇；项目适配器 project.kv（repo、branch、build/lint/test/acceptance、commit.*、doc.repo）。
  • 钉：plan 在 split 时钉哈希；工作流子树对象 HEAD:<prefix> + 脏指纹在 run 初始化钉住；任何漂移都是一次响亮的停车而非静默采用。
  • 学习闭环：stage / pilot 写 observations，postcheck 写 learnings（leak_class ∈ precheck | conformance | gate | novel）→ 收割进 iteration-log/INDEX.md + open/*.md（每条必带可证伪预期）→ 两个独立锚点才提升（structural > script > prose）→ 未经实战的修复进 self-check/validation-debt.md，只凭触发证据关闭。
  • 自检：self-check/check.sh，27 个 checks + 12 个 drills（影子树 + mock CLI 在真实 tmux 里走完整个循环），每条断言两方向（known-bad 必须红），运行前后对树做快照，采集下限拒绝空集合。

5. 三角度评估：完备 · 简洁 · 优雅

5.1 完备

结论：机器一侧近乎完备；人这一腿和「散文里的事实」是两个系统性缺口。 树自己的 70 条未结观察几乎都落在这两类。

强已经封闭的

  • 每个存储读取分辨 fault / absent；每个门有 red-proof；每条断言两方向；采集下限拒绝空集合。
  • 三个循环各有收敛谓词；活性栈六层信号；配额 / 过载 / 重试后端各自有停车类别而非当作 idle。
  • 计划与工作流漂移都被钉住；nonce 围栏防止会话冒充；封闭词汇一处声明。
  • 学习闭环有格式约束（可证伪预期必填；收割数统计是格式不是指令）。

缺还开着的（按机制归并）

  • 人这一腿：停车页面「送达」仍不可观测（park-page-arrival-unobserved）——但 ack 与重发已落地：pager 会重发，launch.sh ack 只暂停一个 notify.ack_timeout 窗口而不终止梯子；pilot 没有收件箱；stop 停的是 ferry 不是 stage；disagreement 停车不带可裁决问题集而 class_u 带。
  • 机器决定却读散文：severity-trend 只读计数，reviewer 早已在散文里写了「全新 / 残留」；refine 因触顶终止只有 1/5 的记录用字段说了；DP / progress 只能追加不能声明「被取代」；ruling 违反被评为 wording 照样过 ready。
  • 观测缺口：implementer 派遣不可见（模型 / effort 是请求不是事实，派遣文本不落盘）；spec 的 claims 只在 emit 时验一次，不在落地 tip 重跑；spec 的 gate 计划与 gates 面没有 join；运行质量（门拒绝数）到 close-out 才可见。
  • 规则 / 输入错配：ruling 只送到命名的 slice；env_sweep 的绝对路径臂把散文里的 /token 读成路径；effort 下限跨模型比较；plan 是被评审最少的工件。

从第一性原理看，这些都是同一个问题：合约（必须成立什么）、机制（代码）、证据（哪次运行）、历史（为何改）四种知识交织在每个文件里。Ousterhout 的判据是注释应降低复杂度而非叙事；Diátaxis 的判据是 reference 与 explanation 必须分家；ADR 的判据是决定不可变、变更即新纪录。树的机制符合这三条，树的文本不符合。

5.3 优雅

优雅之处

  • 「格式不可被点头敷衍，指令可以」——把每条纪律做成必填字段的一贯手法。
  • fault ≠ absent 贯穿每一层：store rc、config、ledger 读取、报告输出。
  • widening（抽象解释）用在 split 循环收敛：在更粗的域（索引字节）上计算不动点。
  • nonce 作 fencing token；tmux 只做结构、CLI 差异全在声明；时钟接缝让活性测试确定化。
  • 学习闭环本身是一个认识论装置：可证伪预期、两锚提升、只凭触发关闭。

不优雅之处

  • 工件合约挂在拼写上而不是事件上：--halt class_u 欠一份问题集文档，verdict 路由到的 class_u 不欠；disagreement 与 class_u 对同一 owner 准备程度相反。
  • 代码是一本日记：日期、topic 名、测量数写在 runtime 注释里，与树自己「正式文档不带讨论代号」的精神相悖。
  • 耐久之家是 Markdown 表格：多 KB 的单元格、正则解析的 blockquote 收割行、「adopted 就删文件、历史进 git」——读者需要 git 考古。
  • 文档之间靠正则检查互相看齐（25-xref、30-closure 的 sweep_subjects、52-vocab）：这是把散文当数据的胶水。
  • bash 到了 9K + 14K 行：awk-in-string 的撇号陷阱同一天踩两次；每次 state_get | grep 都全量 md5。

6. 深度优化方案

第一性原理：① 稀缺资源依次是 owner 注意力、模型时间、维护者注意力；② 机器决定的事实必须是字段，散文给人读；③ 一个事实一个家，其余皆指针或推导；④ fault ≠ absent，缺席必带范围；⑤ 判断流向最便宜的仪器。方案按「已落地 / 下一步 / 结构性」三档，每项给出危害、为何现有机制吸收不了、需求已被谁证明，以及可证伪预期——这是树自己的 admission discipline。

6.1 本回合已落地（P0）

变更解决的缺口证明

A. 学习闭环的家从表格变成记录 —— 已落地（独立回合）
