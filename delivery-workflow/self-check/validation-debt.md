# validation debt

> Rule (design/migration-and-acceptance.md §3): fixes and mechanisms unexercised
> by live traffic get a row here, closed **only on firing evidence** — never on
> re-reading the code. Loaded-baseline doctrine applies: record the machine
> condition when evidence lands. Add a row whenever self-check cannot exercise
> something it asserts about; delete a row only with the evidence cited inline.
>
> **A closes-on conjunct may never rest on a pane-log ABSENCE.** A pane log
> carries the agent's rendered messages, never command output — literals that
> provably occurred can read zero there — so "the log shows no refusal" is
> uninformative in every direction. The transcript the CLI keeps (carried as
> `transcript=` on `notify_events` rows) is the instrument for what a session
> actually ran.
>
> **A closed row that still wants a reading writes `WANTED: <reading>` in one
> of its cells** — `derive_report.sh` §5 asks for every marker in the closed
> table beneath the open worklist, which is the only place anything asks. The
> text is pipe-free like any cell; an open row needs no marker — it is the
> worklist.
>
> **Negative readings are named in the rows on purpose.** Most rows below say
> what a live reading that goes the OTHER way would mean; that reading closes
> the row too, and usually says more about the mechanism than the positive one.
>
> **Back-reference convention (no check enforces it, deliberately):** when a
> harvest touches a row that an open `iteration-log/` entry names, add that
> entry's id to the row. The link is for navigation, not de-duplication.
>
> Open rows count against `maintenance.vd_open_cap` (`check.sh` prints a WARN
> over it); the count and the worklist both stop at the first `##` heading
> below.

## standing (not payable debt — the cap does not count these)

> A row lands here on one of two grounds, and carries its ground in its own
> text so it can be moved back without re-deriving:
>
> - **(a) its firing would itself be a defect, or no store surface can carry
>   its evidence** — the mechanism is proven in both directions by fixtures and
>   only the wiring's live path is unexercised;
> - **(b) three consecutive full-store harvests judged it and nothing fired.**
>
> It is still debt by this file's first rule, so it is not deleted — the fact
> that a guard has never fired for real is exactly what a later firing needs
> somewhere to land. It is not moved to `## closed` either, because that
> table's contract is *closed on firing evidence*. `defaults.kv` states what the
> cap counts — mechanisms genuinely outrunning evidence — and a row evidence
> cannot reach is not that.
>
> **The rule for leaving**: the moment one of these fires it moves back up to
> the open table with the firing quoted, and is closed from there like any
> other row. `check.sh`'s maintenance WARN and `derive_report.sh`'s worklist
> both stop at this heading explicitly, not by position.
